## 7233da57, M: location_parking_distances, data layer only
For the "minutes from the car park" fact on place pages and the My day
planner v1 (fed18dd4). This task ships the table, the script that fills it
and a tested reader. No UI, no page data method change, so no preview gate.
1. `migrations/create_location_parking_distances.sql` (NOT applied):
   `location_parking_distances` (id uuid pk default gen_random_uuid(),
   location_id uuid not null fk locations on delete cascade,
   parking_location_id uuid not null fk locations on delete cascade,
   walking_seconds int not null check (walking_seconds >= 0),
   distance_meters int not null check (distance_meters >= 0),
   method text not null default 'mapbox_walking' check (method in
   ('mapbox_walking')), computed_at timestamptz not null default now(),
   unique (location_id, parking_location_id)); index on location_id; RLS on
   with a public select policy in the same file (same shape as `stories`).
   Add it to `docs/schema-reference.md` Part 1 marked "pending apply".
   Use `distance_meters`, never `distance_km`.
2. `scripts/compute-parking-distances.mjs`: car parks = published locations
   whose category slug is `parking`, category resolved by slug scoped to the
   Barbizon town (slug subquery, never a hardcoded UUID); origins = every
   other published location with coordinates. One Mapbox Matrix API call per
   batch (profile `mapbox/walking`, at most 25 coordinates per request, so
   batch origins against the 6 car parks). Token from `MAPBOX_SECRET_TOKEN`,
   falling back to `NEXT_PUBLIC_MAPBOX_TOKEN`. Default is a dry run that
   writes `exports/parking-distances-<date>.sql` (idempotent upserts on the
   unique key) and prints a summary; `--execute` upserts through the service
   role client, refuses to run without the table, and is Luigi's action, not
   the loop's. Never compute a straight-line fallback: a pair Mapbox cannot
   route is skipped and listed. Mock `fetch` in tests; do not call Mapbox
   from the loop.
3. `lib/parkingDistance.ts`: pure `nearestParking(rows)` returning the
   closest car park by walking_seconds (ties by distance_meters), and
   `fetchNearestParking(supabase, locationId)` that returns null on any error
   or missing table (wrapped like the existing `degrade(...)` reads).
   Minutes rounding: ceil(seconds / 60).
4. Tests: `lib/parkingDistance.test.ts` (nearest, ties, empty, error to
   null) and `scripts/compute-parking-distances.test.mjs` (batching at 25,
   skip unroutable pairs, SQL output escapes names, no straight-line rows).
